# 已知差距与设计定位

本文件是限制清单的**唯一权威位置**。其它文档只允许一句话摘要并链接到本文件对应条目。

分两类：**G1–G5 是待闭合的契约缺口**（有收口标准，修完即删行）；**G6–G12 是明确的设计定位或环境约束**（不计划修复，改动前需先改 ADR）。

## 一、待闭合的契约缺口

| # | 位置 | 目前可观察的行为 | 收口标准 |
| --- | --- | --- | --- |
| G1 | Follower 对账 | 定期合并能补新增；收到权威空集合时仍可能保留因漏广播而过期的本地记录 | 成功空快照与查询失败可区分；以完整快照移除过期记录，同时保留查询开始后已观察到的更新 |
| G2 | 数据后端兼容过滤 | `EndpointRecord.backend` 已存在，但 Core 的连接与就绪路径尚未统一应用该标识 | 同名兼容与不兼容端点共存时，注册、发现快照、连接选择与就绪判定使用同一规则 |
| G3 | RPC 时限与取消 | 排队、发现查询与同步拨号可能延长调用等待；`kSending` 在实际提交前建立 | 如对外承诺等待上限：排队到期须及时兑现，发现与建连共用剩余预算；发送前取消的承诺须对应可验证的提交边界 |
| G4 | 构建依赖边界 | 聚合目标仍传递 `src/` 搜索路径；运行时入口仍直接包含 NNG Registry 私有头 | 应用仅依赖公共 include 根；运行时仅经注入入口引导具体后端 |
| G5 | 运行时 schema 协商 | 无版本协商；两端需自行保持 protobuf 字段兼容 | 若引入协商：定义版本字段位置、缺失版本时的默认行为与不兼容时的失败码 |

## 二、设计定位与环境约束

| # | 项目 | 结论 |
| --- | --- | --- |
| G6 | 内存后端的范围 | 进程内共享总线，**不与 NNG 或其它进程互通**。定位为契约测试与无 NNG 构建验证，非生产推荐。跨进程线兼容由 NNG 后端与 `interop_helper` 覆盖 |
| G7 | 全局 `Shutdown()` 的级联 | 只置标志，不关闭端点 socket、不停端点线程，回调仍可能触发。端点须单独 `Shutdown()`/析构后再 `Clear()`。见 [contracts.md](contracts.md) §1 |
| G8 | QoS 协商、背压与 mps 限流 | 只有统计，没有机制。`QosProfile::reliability` 两种取值当前行为一致（均为尽力投递） |
| G9 | 跨进程同名端点冲突与请求幂等去重 | 未实现。同名服务跨进程可共存；有副作用的请求需业务自带幂等键 |
| G10 | Registry 回调持锁派发、`RuntimeConfig` 外部装配 | 未实现。Watch 回调在派发锁内执行，因此禁止重入 Registry |
| G11 | 二进制 ABI | 无稳定 ABI 承诺。源码级 `[[deprecated]]` 兼容已提供；返回类型变更即 ABI 不兼容，真正的二进制灰度需版本化 soname |
| G12 | 新生产后端与 NNG 进程互通 | 需要共同线上协议或桥接，当前未实现。`backend` 字段可用于过滤不兼容地址（与 G2 相关） |

## 三、测试环境的已知抖动

| # | 现象 | 处置 |
| --- | --- | --- |
| EV1 | `cross_pubsub_legacy_to_new` 在 `ctest -j6` 高负载下偶发 follower registry REQ 3 秒超时、缺 `LEGACY_PUB_OK` | `scripts/verify.sh` 只对这类失败做最多 3 次有限重试并留日志，其它失败立即报错。**不得**通过放宽断言或删除用例"修绿" |
| EV2 | 同一 OFF 构建目录在不同 `CMAKE_PREFIX_PATH` 间反复重配，会让静态库归档与可执行文件来自不同轮次产物（`backend_contract_memory` 稳定 SegFault） | `verify.sh` 把 OFF 构建目录与依赖前缀绑定，换前缀即换目录；全新目录稳定通过 |

## 维护规则

- 修掉一条缺口：删除该行，并在同一 PR 更新 [contracts.md](contracts.md) 的对应断言与登记新测试。
- 新增一条限制：在本文件加行，同时在引入处（指南或契约）加一句链接，不重复描述。
- 把 G 编号挪作它用或复用时，必须检查全仓库引用：`grep -rn "known-gaps.md" docs/`。
